# HEC Map Data

Published map layers for HomeEnergy ConneCT. Generated files only, no code. The code
that writes them lives in
[hec-automation](https://github.com/IHeartMyHomeCt/hec-automation).

This repo is public on purpose. It exists so a mapping tool can read the layers over
plain HTTPS with no API key, no sign-in and no sharing setting to get wrong.

## Why this exists

Google Drive is built to show files to people, so it answers a request with a page
rather than the file whenever it wants to check who is asking. A mapping tool asks for
KML, gets a web page, and finds no pins. GitHub's raw host just returns the bytes, and
it sends the `Access-Control-Allow-Origin: *` header that browsers require before they
will read a file from another site. That removes the whole class of problem.

## Layers

| File | Contents | Source |
|---|---|---|
| `layers/contractors_ect.kml` | Energize CT approved contractors | Airtable, Contractors / Energize CT map view |
| `layers/contractors_ie.kml` | HES-IE income eligible contractors | Airtable, Contractors / Income eligible view |
| `layers/remediators.kml` | Health and safety remediators | Airtable, Contractors / Remediators view |

Each carries business name, phone, town and services. All of it is public roster
information.

## What must never be committed here

**No participant data. No household coordinates.** Full-precision latitude and
longitude reverse-geocodes to a street address, so a participant point is identified
household data even with no name or address attached to it. Participant layers stay on
a Workspace surface behind Google sign-in.

`.gitignore` blocks the obvious filenames as a backstop. Do not rely on it. The rule is
the rule.

A funder-facing participant view means counts aggregated to town or census tract. A
tract count is not participant data and can be published here.

## Using a layer in uMap

Create a layer, open **Remote data**, and set:

- **Url**: the `raw.githubusercontent.com` URL for the file
- **Format**: `kml`
- **Proxy remote data**: leave off. It is not needed here, because this host already
  sends the CORS header.

## Updating

Regenerated by the nightly Apps Script run. Do not hand-edit a layer file; the next run
overwrites it.
